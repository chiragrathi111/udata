Kubernet is an open source Container management tool (Orchestration tool)
Which automate Container scaling & Load Balancing.
All top cloud provider suppot K8s.
Kubernet is a master-slave or client-server tool
Architecture.
Master Node:
1. API Server: Expose REST API to interact with cluster.
2. Scheduler: Schedule the container on worker node based on resource availability.
3. Controller Manager: Monitor the cluster and make necessary changes.
4. etcd: Distributed key-value store to store cluster data.
Worker Node:
1. Kubelet: Agent that runs on each worker node and communicate with master node.
2. Kube-proxy: Network proxy that runs on each worker node and maintain network rules
3. Container Runtime: Software that runs the containers (e.g., Docker, containerd)
Key Concepts:
1. Pod: Smallest deployable unit in K8s, can contain one or more
    container
2. Service: Abstraction that defines a logical set of Pods and a policy to access them.
3. Deployment: Declarative updates for Pods and ReplicaSets.
4. Namespace: Virtual cluster within a K8s cluster to separate resources.
Basic Commands:
1. kubectl get nodes: List all nodes in the cluster.
2. kubectl get pods: List all pods in the cluster.
3. kubectl create -f <file.yaml>: Create resources from a YAML file.
4. kubectl apply -f <file.yaml>: Apply changes to resources from a YAML file
5. kubectl delete -f <file.yaml>: Delete resources defined in a YAML file.
6. kubectl describe pod <pod-name>: Get detailed information about a specific pod.
7. kubectl logs <pod-name>: View logs of a specific pod.
8. kubectl exec -it <pod-name> -- /bin/bash: Access the shell
of a specific pod.
Kubernet supports various networking models, storage options, and can be extended using custom resources and controllers.

Kubernet is widely used for deploying, scaling, and managing containerized applications in production environments.
